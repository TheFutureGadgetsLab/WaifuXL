# Repository Guidelines

## Project Structure & Module Organization
- `src/app/` contains Next.js App Router routes; each page lives in a folder with `page.tsx` (e.g., `src/app/about/page.tsx`) and shared layout in `src/app/layout.tsx`.
- `src/components/` holds UI components organized by domain (`layout/`, `sidebar/`, `modal/`, `feedback/`, `display/`).
- `src/hooks/` contains reusable hooks like `useUpscale.ts` and `useResponsive.ts`.
- `src/services/` handles inference, utilities, and Zustand stores under `src/services/stores/`.
- `public/` stores static assets, including `public/models/*.onnx`, `public/images/`, and `public/tags.json`.
- `out/` is the static export output generated by `next build`; do not edit by hand.

## Build, Test, and Development Commands
- `npm run dev` starts the Next.js dev server.
- `npm run build` builds the app; in production it exports a static site to `out/` (see `next.config.mjs`).
- `npm run start` serves the static `out/` folder via `serve`.
- `npm run lint` / `npm run lint:check` run ESLint over the repo.
- `npm run format` / `npm run format:check` apply or verify Prettier formatting.

## Coding Style & Naming Conventions
- TypeScript + React; use `.tsx` for components and `.ts` for non-UI modules.
- Follow existing formatting (Prettier defaults); run `npm run format` before pushing.
- Components use PascalCase filenames (`PageLayout.tsx`); hooks use `useX.ts` in `src/hooks/`.
- Store modules live in `src/services/stores/` and typically use descriptive camelCase names (e.g., `imageStore.ts`).

## Testing Guidelines
- No automated test framework is configured and `tests/` is currently empty.
- For changes, at minimum run `npm run lint` and `npm run build` to catch issues.
- If you add tests, place them under `tests/` and document the new command in `package.json`.

## Commit & Pull Request Guidelines
- Recent history uses short, informal messages (e.g., "misc", "update onnx"). Keep commits concise but meaningful about the change.
- For PRs, include a clear summary, list of tests run, and screenshots for UI changes.
- For larger feature ideas, open a discussion first, per the guidance in `README.md`.

## Configuration & Runtime Notes
- `next.config.mjs` sets COOP/COEP headers and switches to `output: 'export'` outside development; keep these in mind when changing routing or headers.
- Model assets in `public/models/` are loaded in the browser; if updating them, keep filenames stable or update any references accordingly.
